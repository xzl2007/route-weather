# RouteWeather 2.0 · 山途智行

**在线预览（手机可直接打开）：** [RouteWeather 2.0](https://xzl2007.github.io/route-weather/)

> 面向山区自驾的路线气象分析与出行决策辅助工具。出发前输入路线，查看沿途天气变化、需要重点关注的区段和更合适的出发时间：
> 明天这条路适不适合走、几点出发更稳、每个关键点与沿途采样点是什么天气、行程中哪里需要调整。

**不是预警发布平台，也不是替代导航的安全工具，而是面向山地出行的「路线天气体检」。**

## 2.0 产品体验

- 首页提供行程入口、本机历史与核心能力说明；路线编辑、天气分析和完整报告沿用原生 HTML / CSS / JavaScript。
- 导航模式将 OSRM 返回的真实道路几何按累计里程切段，并复用原有逐点天气影响分级着色。点击路线段、采样标记或采样清单可查看对应天气详情。
- 天气字段缺失时使用中性灰区段并说明数据不足。规划模式仍按关键点位间的直线估算，不显示成真实道路路径。
- 评分、阈值、天气权重、到达时间计算和出发时间比较逻辑保持原样。地图颜色是天气影响参考，不代表道路安全等级。
- PWA 名称、主题色、图标和 Service Worker 缓存已更新。

### 页面与交互

- **探索首页**：介绍产品能力，进入路线规划、示例路线和本机行程收藏。`?demo=1` 会预置示例路线，但仍从探索首页进入。
- **路线规划**：地图作为主视觉背景，支持地点搜索、地图选点、拖动排序、规划/导航模式和点位时间设置。
- **路线地图**：地图铺满分析画布，天气影响沿真实路网分段着色；顶部章节导航悬浮在地图上。
- **智能报告**：路线横幅与评分卡共用内容宽度，集中展示建议出发时间、风险提示和重点路段。
- **沿途天气、出发时段、完整报告**：各自使用独立报告页；章节导航浮在顶部风景横幅上，手机窄屏下导航在胶囊内横向滚动。
- **行程收藏**：在当前设备保存、筛选和回看历史，不需要账号。

布局适配桌面和手机屏幕，地图缩放控件、浮层和底部操作区会为小屏重新排布。

## 它解决什么问题

天气 App 告诉你「雅安明天有雨」，地图导航告诉你「这条路怎么走、要多久」。
但很少有人直接回答：

> 我这条 **雅安 → 天全 → 泸定** 的行程，按现在安排走是否合理？
> 哪个时段、哪一段路的天气更容易出问题？应该把出发时间调到几点？

路线天气体检把**逐小时气象预报、海拔、路线采样和行程时间**放在一起，输出面向整条行程的天气评估。

| 产品 | 评估单位 | 主要回答 |
|---|---|---|
| 天气 App | 一个城市或点位 | 会不会下雨、气温多少 |
| 地图导航 | 一条道路 | 怎么走、大概多久 |
| **路线天气体检** | **一条行程** | **这条路线当前安排是否合适，时间怎么调** |

## 怎么用

1. **输入路线**：可用地图选点、搜索地名或从内置点位库添加；最多 5 个关键点位。
2. **选择模式**：
   - 规划模式：自己安排每个关键点位的出发/到达时刻；
   - 导航模式：只给起点、终点及可选途经点，由系统计算路网路径和预计到达时间。
3. **开始体检**：系统生成路线评分、关键点位天气、沿途采样、逐小时天气和出行建议。
4. **调整时间**：规划模式可整体平移行程；导航模式可对比原出发时刻前后 2 小时的路线分，并一键采用推荐时刻。

**无需注册、无需登录。** 行程历史保存在浏览器本地，不会上传到本项目服务器。

## 两种模式

| | 规划模式 | 导航模式 |
|---|---|---|
| 输入 | 2–5 个关键点位 + 每个点位的时刻 | 起点、终点，可选途经点 |
| 时间来源 | 用户自行安排 | 当前时间或用户指定时刻，按路网预计时长推算 |
| 路程估算 | 点位间直线距离 × 1.25 近似 | OSRM 真实路网路径 |
| 天气取哪一刻 | 每个采样点取计划到达时刻 | 每个采样点取预计到达时刻 |
| 主要输出 | 路线分、采样表、逐小时对比、出行建议 | 路径、预计到达时间、沿途天气、采样表、天气提醒 |

### 时间口径

- 第一个关键点位显示的时间是**出发时刻**；
- 其余关键点位显示的时间是**到达时刻**；
- 沿途采样点的时刻按其在路段中的位置插值计算。

---

## 核心能力

- **关键点位 + 沿途采样**：除用户输入的点位外，在路段中间自动加入采样点，避免只看起点和终点。
- **逐小时天气**：每个关键点位展示行程日 24 小时天气，点击任一小时可切换查看；默认高亮该点的出发或到达时刻。
- **出发时刻调整**：
  - 规划模式提供基准日起连续 3 天、08:00–20:00 的逐小时起点适宜度，点击后整体平移整份行程；
  - 导航模式只展示预计到达时刻的逐小时天气状况，不计算也不展示路线评分。
- **可解释评分**：每个低分采样点给出主要原因，高分点显示「天气良好」，不展示内部扣分明细。
- **地形辅助**：地图支持「普通」与「地形」两种底图，可全屏选点与查看路线。
- **本地历史与分享**：可在本机保存行程，并复制分享链接、摘要或打印为 PDF。

## 评分规则

### 1. 单点评分

每个采样点取**预计到达那一小时**的天气，从 100 分开始扣分：

| 因素 | 扣分规则 |
|---|---|
| 降水概率 | >20% 扣 5；>40% 扣 12；>60% 扣 22；>80% 扣 35 |
| 小时降水量 | >0 mm 扣 3；>0.5 mm 扣 10；>2.5 mm 扣 20；>8 mm 扣 35 |
| 风速 | >18 km/h 扣 5；>29 扣 12；>40 扣 20；>50 扣 30 |
| 气温 | 舒适区 12–26℃；偏离后每满 5℃ 扣 5，最多扣 20 |
| 结冰风险 | 气温低于 0℃ 再扣 10 |
| 天气现象 | 按 WMO 天气码扣 3–25 分，例如小雨 5、中雨 12、大雨 20、雷暴或冰雹 25 |
| 高海拔 | 超过 3000 m 扣 5 |

```text
点位分 = max(0, 100 - 所有扣分项之和)
```

### 2. 分数等级

| 分数 | 等级 | 含义 |
|---|---|---|
| 80–100 | 🟢 适宜 | 适合出行 |
| 60–79 | 🟡 一般 | 可以出行，注意天气变化 |
| 40–59 | 🟠 谨慎 | 谨慎出行 |
| 0–39 | 🔴 不建议 | 不建议出行 |

### 3. 路线总分

规划和导航模式使用同一套路线综合分：

```text
平均分 = round(所有采样点分数的平均值)
路线分 = round(平均分 × 0.7 + 最低分 × 0.3)

若最低分 < 40，则路线分最高为 59
若 40 ≤ 最低分 < 60，则路线分最高为 79
若最低分 ≥ 60，则采用初始路线分
```

因此，路线分既考虑整条路线的平均水平，也用 30% 权重和封顶规则突出最差采样点。若出行日期是今天，导航模式会在当前时间至未来 4 小时内寻找「全程最低分最高」的出发时刻；若未来 4 小时都不可用，再继续在当天剩余时段中寻找。

### 4. 出发时刻对比说明

规划模式中的「出发窗口 · 全程评分」会针对每个候选出发小时重新计算整条路线，因此格子中的数字就是**该时刻出发的全程评分**。点击某一格后，系统会把整份行程平移到该时刻，并重新计算报告。

## 采样方式

### 规划模式

- 在相邻关键点位之间按直线等距插值；
- 约每 8 km 一个采样点，单段最多 12 个，全线最多 20 个采样点（含关键点位）；
- 长路段的实际采样间隔会大于 8 km；
- 采样点时刻在相邻关键点位的两个时刻之间线性分配；
- 采样点海拔来自公开高程数据，仅用于天气评分参考。

### 导航模式

- 使用 OSRM 计算路网路径；
- 沿实际路径按里程等距采样；
- 采样点数按行程时长加密到 8–12 个，避免只看起终点；
- 每个采样点的预计到达时刻 = 出发时刻 + 行程进度 × 总预计时长；
- 导航模式仅展示天气、温度、降水、风速和影响，不展示数字评分；
- 徒步/骑行目前也使用公路路网并替换估算速度，不能替代真实步道或绿道数据。

| 用途 | 来源 | 授权/说明 |

| 逐小时天气、海拔 | [Open-Meteo](https://open-meteo.com/) | CC BY 4.0 |

| 地图备用底图 | OpenStreetMap / Esri | 按各自署名要求使用 |

报告页会固定显示数据来源与更新时间，并明确区分：

> 天气数据来自 Open-Meteo；适宜度评分与行程结论由本作品计算生成。

### 隐私

- 不采集姓名、手机号等身份信息，无需登录；
- 行程点位、时间和历史记录仅保存在浏览器本地存储中，不上传到本项目服务器；
- 天气查询会向 Open-Meteo 发送采样点坐标，路径规划会向 OSRM 发送路线坐标；
- 分享链接会把路线点位编码进 URL，收到链接的人可以看到该路线信息；
- 清除浏览器站点数据会删除本地行程历史。

## 已知限制

1. **采样点之间仍未逐米评估**：沿途采样提高了覆盖率，但无法代表采样点之间的全部路况与天气变化。
2. **规划模式不是真实路径规划**：路段长度按直线距离 × 1.25 估算，采样点也按点位间直线插值，不能替代真实道路或步道。
3. **导航到达时刻为估算值**：按 OSRM 平均时长推算，未考虑堵车、休息、封路、施工等实际情况，山区行程建议预留 20–30% 时间余量。
4. **山区局地预报精度有限**：公开全球模型难以完全刻画峡谷、山脊和局地强对流。
5. **地名搜索依赖网络**：天地图不可用时，只保留内置点位库与已有坐标。
6. **不发布预警、不提供实时路况**：本作品只做行程天气参考，不替代气象、自然资源、水利等部门发布的官方预警。
7. **尚未实现**：订阅提醒、长图导出、多行程并排对比。

> **本作品为参考性评估，不构成安全保证，不替代官方预警信息与现场判断。**

## 本地运行与验证

项目没有构建步骤。可在项目根目录运行：

```powershell
python -m http.server 8000
```

然后访问 `http://localhost:8000/`。由于地图、地名搜索与天气使用浏览器端网络 API，请使用联网环境；`file://` 方式不会注册 Service Worker。

当前自动化脚本：

```powershell
node test/nav-test.js
node test/plan-test.js
node test/edge-test.js
```

`test/algo-test.js` 会请求 Open-Meteo 实时天气与海拔数据，需要外网可用。
